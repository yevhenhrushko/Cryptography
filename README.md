# Учебный проект по криптографии

## Демонстрация атак RSA

Java 21 и Gradle Wrapper уже настроены в проекте. Запуск лабораторной работы:

```bash
./gradlew rsaAttacks
```

Точка входа — `RsaAttackDemo.main`, программный запуск — `RsaAttackDemo.runExamples()`.
Каждый из восьми примеров шифрует ровно `Hello World` в UTF-8 существующим `RsaHelper`,
проверяет обычное расшифрование своей тестовой парой ключей и восстанавливает сообщение атакой.
Консоль показывает открытые параметры, шифротекст, промежуточные вычисления и совпадение результата.
В конце должно быть: `Результат: 8/8 атак восстановили Hello World.`

[Сохраненный вывод проверенного запуска](docs/rsa-attacks-example.txt) содержит все числовые шаги.

Ключи специально конструируются с известными слабостями **только в памяти**.
Существующие ключи на диске не используются. Подбор простых чисел воспроизводим,
поэтому эти параметры подходят только для лабораторной работы.
Используется textbook RSA: `c = m^e mod n`, без случайного дополнения (padding).

| Атака | Специальная слабость | Как восстанавливается сообщение |
|---|---|---|
| Ферма | Соседние простые `p` и `q` | Перебор `a` от `ceil(sqrt(n))`: если `a² − n = b²`, то `p = a − b`, `q = a + b` |
| Общий простой множитель | Два разных модуля содержат один `p` | `p = gcd(n1, n2)`, затем `q = n1 / p` |
| Малая открытая экспонента | В демо `e = 5`, нет padding, `m⁵ < n` | Точный целочисленный корень степени `e`; хелпер поддерживает и другие допустимые `e` |
| Хастад | То же самое `m`, три получателя с `e = 3`, попарно взаимно простые модули | CRT восстанавливает `m³` из трех шифротекстов; затем извлекается кубический корень |
| Винер | `d = 5`, сбалансированные простые | Подходящие дроби `e/n` дают кандидатов `k/d`; проверяем `phi = (ed − 1)/k` и множители `n` |
| Поллард p−1 | Все простые множители `p−1` не больше 17 | Последовательное возведение основания в степени малых простых и `gcd(a−1,n)` раскрывают множитель |
| Общий модуль | Одно сообщение и `n`, взаимно простые `e1 = 17`, `e2 = 65537` | Безу: `u*e1 + v*e2 = 1`, затем `m = c1^u*c2^v mod n` |
| Franklin–Reiter | Один ключ с `e = 3`, известная связь `m2 = 2*m1+7 mod n` | Линейный НОД многочленов `x³−c1` и `(2*x+7)³−c2` раскрывает `m1` |

После факторизации вычисляются `phi(n) = (p − 1)(q − 1)`, `d = e^(-1) mod phi(n)`,
затем `m = c^d mod n`. Малая `e`, Хастад, общий модуль и Franklin–Reiter восстанавливают сообщение
без восстановления приватного ключа.
В примере Хастада `m³ > n_i` для каждого получателя: простой корень из отдельного шифротекста
не помогает, нужны все три. При `m < min(n_i)` произведение `n1*n2*n3` больше `m³`.

Для классического результата Винера достаточно `q < p < 2q` и `d < n^(1/4)/3`
при `ed = 1 mod phi(n)`; в коде каждый кандидат дополнительно проверяется факторизацией.
Большая открытая экспонента сама по себе не защищает от слишком маленькой приватной экспоненты.

В примере Полларда `p−1 = 2^5 * 3^5 * 5^3 * 7^2 * 11 * 13 * 17`. Сначала
`RsaKeyValidator` отклоняет этот ключ по проверке `SMOOTHNESS`, затем атака использует ту же слабость.
Валидатор уже удаляет все степени малых простых пробным делением; он не ограничивается проверкой размера числа.
Поллард реализован как один проход с основанием 2 по алгоритму 3.14 из HAC: для каждого простого
`r <= B` берётся максимальная степень `r^k <= n`. Граница `B` ограничена диапазоном 2–100000;
это ограничение объёма работы, а не времени. Если НОД равен `n`, проход завершается без результата.

Общий модуль требует обратимых шифротекстов: отрицательные коэффициенты Безу используют
обратные элементы. Эта версия сообщает о неприменимости, если обратного элемента нет.
Franklin–Reiter реализован для `e = 3` и известного аффинного преобразования; возвращает первое сообщение.
Коэффициент `a` должен быть обратим, `b` не должен быть нулём по модулю `n`.
При необратимом промежуточном коэффициенте или нелинейном НОД возвращается объяснённый пустой результат.
Обе атаки проверяют результат повторным шифрованием под исходные два шифротекста.

## Хелпер и собственная тестовая пара

Алгоритмы находятся в `src/main/java/com/cryptography/rsa/RsaAttackHelper.java`.
Их аргументы — открытый ключ и шифротекст; для общего множителя нужен еще один открытый ключ,
для Хастада — три ключа и три шифротекста, для общего модуля — две пары открытых данных,
для Franklin–Reiter — два шифротекста и известные `a`, `b`. Приватную часть методы атак не принимают.

Пример внутри Java-кода, со своей тестовой парой в памяти:

```java
import com.cryptography.rsa.RsaAttackHelper;
import com.cryptography.rsa.RsaHelper;
import java.math.BigInteger;

// Намеренно близкие простые; n достаточно велик, чтобы вместить Hello World целиком.
BigInteger p = BigInteger.ONE.shiftLeft(48).nextProbablePrime();
var testKeys = RsaHelper.generateKeyPair(p, p.nextProbablePrime());
var results = RsaAttackHelper.checkKeyPair("Hello World", testKeys, 10_000);

for (var result : results) {
    System.out.println(result.type() + ": " + result.recoveredMessage());
    result.steps().forEach(System.out::println);
}
```

Если пара уже получена вашим кодом, передайте ее вместо `testKeys`.
`checkKeyPair` сначала проверяет шифрование/расшифрование конкретной строки приватной частью,
затем вызывает Ферма, малую `e` и Винера, передавая только публичные данные.
Это проверка данного сообщения, а не доказательство полной корректности пары ключей.
Строка должна быть непустой и помещаться в модуль (`m < n`); ограничения преобразования строк
совпадают с `RsaHelper`, в частности ведущие нулевые байты не сохраняются.

`AttackResult.recoveredMessage()` содержит `Optional<BigInteger>`: найденное число или пустой результат.
`steps()` объясняет вычисления либо причину неприменимости. Для Ферма задается лимит проверяемых
значений `a`; в журнале сохраняются первые восемь шагов и результат, чтобы не создавать огромный отчет.
**Неудача атаки не доказывает стойкость ключа.** Здесь реализованы конкретные учебные случаи,
а не универсальный взлом RSA или полный аудит криптосистемы.

## Проверки

```bash
./gradlew test --tests com.cryptography.rsa.RsaAttackHelperTest --tests com.cryptography.rsa.RsaAdditionalAttackTest -x processResources -x processTestResources
```

Тесты покрывают восстановление без приватного ключа, все восемь сценариев с `Hello World`,
лимит Ферма, неточные корни, неприменимые экспоненты, одинаковые и невзаимно простые модули,
разные сообщения у получателей, неверные входные данные и контроль переданной пары ключей.
Дополнительно проверяются связь Полларда с валидатором, отрицательные коэффициенты Безу,
связанные сообщения с редукцией по модулю, необратимые коэффициенты многочленов,
корни для `e = 3, 5, 7, 17`, огромная экспонента и сообщения 0 и 1.
Есть воспроизводимый контрольный ключ, проходящий валидатор: все восемь атак возвращают пустой
результат при отсутствии необходимых условий в заданных пределах. Размер ключа сам по себе
не препятствует атакам общего модуля или связанных сообщений при нарушении правил использования.
Эта команда запускает только новые тесты в памяти; ресурсы им не нужны.

## Эксперимент со своим публичным ключом: 3 минуты замера

```bash
./gradlew rsaKeyAttackTest -PrsaPublicKey=Keys/<имя>_public.key
```

Для уже использованного в эксперименте ключа готовая команда:

```bash
./gradlew rsaKeyAttackTest -PrsaPublicKey=Keys/20261002_231554_public.key --console=plain
```

По умолчанию Ферма использует **все логические процессоры, доступные JVM**: один рабочий поток
на процессор. Потоки динамически получают разные блоки по 256 кандидатов из общей очереди;
один кандидат не проверяется двумя потоками. Быстрый фильтр квадратных остатков по модулю 4032
отбрасывает заведомые неквадраты до дорогого `BigInteger.sqrt`. Разность квадратов внутри блока
обновляется сложением. Короткие проверки малой экспоненты и Винера остаются последовательными.

В отчете указаны доступные процессоры, число активных потоков, кандидаты и извлечения корня
по каждому потоку, а также среднее число занятых ядер по суммарному CPU-времени потоков.
Это позволяет отличить настройку «16 потоков» от фактически выполненной параллельной работы.
Загрузка остальных приложений, сборка мусора и различия ядер влияют на результат;
гарантировать постоянную загрузку каждого физического ядра Java не может.

Для сравнения с одним потоком или короткой проверки:

```bash
./gradlew rsaKeyAttackTest -PrsaPublicKey=Keys/20261002_231554_public.key -PrsaAttackThreads=1 -PrsaAttackSeconds=5
./gradlew rsaKeyAttackTest -PrsaPublicKey=Keys/20261002_231554_public.key -PrsaAttackSeconds=5
```

`rsaAttackThreads` принимает 1–256; без параметра используется `Runtime.availableProcessors()`.
Gradle запускает один тестовый процесс с лимитом heap 2 ГБ; параллельный поиск выполняется внутри него.

Выберите конкретный публичный ключ: тест не переключается молча на другую пару.
`RsaPublicKeyAttackTest` загружает только публичную часть и вызывает
`RsaHelper.encryptText("Hello World", key)`. Таким образом, шифротекст создается заново
выбранным ключом; приватная часть не нужна. Обычный запуск `test` пропускает этот эксперимент.
При ручном запуске из IDE нужны JVM-параметры `-Drsa.attack.enabled=true`
и `-Drsa.publicKey=Keys/<имя>_public.key`. Дополнительно доступны `-Drsa.attack.threads=1`
и `-Drsa.attack.seconds=5`.

Порядок эксперимента:

1. Измеряется шифрование и проверка известного кандидата `Hello World` публичным ключом.
   Textbook RSA детерминирован: совпадение шифротекстов позволяет подтвердить догадку о сообщении,
   даже если факторизация модуля недоступна. Это не восстановление приватного ключа.
2. Проверяются реализованные случаи малой открытой экспоненты и атаки Винера.
3. Если они не восстановили сообщение, запускается отдельный замер Ферма (по умолчанию три минуты).
   Поиск останавливается по монотонным часам; interrupt также завершает цикл.

Бюджет **самого замера Ферма по умолчанию — 180 секунд (3 минуты)**. Параметр `rsaAttackSeconds`
принимает целое число от 1 до 3600: например, `-PrsaAttackSeconds=300` задаёт пять минут.
Загрузка ключа, шифрование, предварительные проверки и сохранение отчета не вычитаются из бюджета.
Тайм-аут JUnit равен выбранному бюджету плюс 20 секунд резерва; тайм-аут задачи Gradle —
бюджету плюс 30 секунд с учётом запуска и остановки тестового процесса.
Одна операция `BigInteger` неделима, поэтому это ограничение процесса, а не гарантия реального времени
при остановке ОС/JVM. Для короткого запуска можно указать `-PrsaAttackSeconds=5`.
При успешном восстановлении сообщения поиск завершается раньше.

Результаты сохраняются в `docs/rsa-key-benchmark-latest.txt`, новое число шифротекста —
в `docs/rsa-current-ciphertext.txt`. Следующий эксперимент заменяет эти два файла.
Отдельная копия каждого нового отчета сохраняется в `docs/benchmarks/` с временем UTC
и числом потоков в имени. В конце консольного вывода есть краткая сводка: время эксперимента,
число кандидатов, скорость, условная оценка в годах и время подтверждения `Hello World`.
Числа измеряются заново и не обязаны совпадать с предыдущим запуском.
Большие значения выводятся в виде `2,8 × 10²⁴⁵¹ лет`, диапазоны —
`4,84 × 10²⁴⁵³ — 1,936 × 10²⁴⁵⁴ лет`: десятичная запятая и показатель степени верхним индексом.
Отчет содержит имя выбранного публичного ключа, размер `n`, `e`, отпечатки модуля и шифротекста,
фактически затраченное время и число проверенных кандидатов. `PASSED` означает корректное
выполнение измерения, **а не доказанную криптостойкость**.

### Как понимать оценку в годах

Ферма ищет `a = (p + q)/2` от `ceil(sqrt(n))`. Без знания `p` и `q` неизвестно,
на какой итерации будет ответ: после неудачного трехминутного поиска ответ может оказаться
даже следующим кандидатом. Поэтому прогноз времени взлома текущего ключа по такому замеру невозможен.

В отчете приведена **условная экстраполяция полного диапазона**. Если `p > q` и `p/q < 2`
(например, простые одной битовой длины), то:

```text
a <= floor(sqrt(9*n/8))
число кандидатов = floor(sqrt(9*n/8)) - ceil(sqrt(n)) + 1
условные оставшиеся годы = оставшиеся кандидаты / скорость / 31 557 600
```

Это верхняя граница размера диапазона при указанном условии; для конкретных неизвестных
множителей ответ может находиться значительно раньше. Расчет использует `BigDecimal`,
поэтому даже для модуля в 16 384 бита значение не превращается в `Infinity`.
Диапазон при скорости вдвое выше/ниже показывает только чувствительность к скорости;
он не является статистическим интервалом. Стоимость шага при дальнейшем поиске меняется.
Метод GNFS и остальные возможные атаки этим замером не оцениваются.
В параллельном запуске учитываются уникальные проверенные кандидаты; на момент остановки
в частично обработанных блоках могут оставаться пробелы. При расчете оставшегося диапазона
вычитаются только кандидаты, попавшие в границы этой модели. Скорость включает быстрые
отказы фильтра остатков, поэтому число кандидатов и число дорогих извлечений корня различаются.

Быстрые тесты таймера, счетчика, восстановления и формулы оценки:

```bash
./gradlew test --tests com.cryptography.rsa.RsaFermatBenchmarkTest -x processResources -x processTestResources
```

## Реальная история и источники

Оригиналы шести основных материалов скачаны в [docs/sources](docs/sources/README.md).
Там находятся пять PDF и полный текст RFC 8017, а также индекс со ссылками на оригиналы.

- **Mining Your Ps and Qs (USENIX Security 2012).** Исследователи восстановили RSA-приватные
  ключи для 0,50% обследованных TLS-хостов и 0,03% SSH-хостов: из-за недостаточной энтропии
  разные публичные модули имели общий простой множитель. Демонстрация `SHARED_PRIME`
  воспроизводит математический механизм на искусственных данных.
  [Исследование](https://www.usenix.org/system/files/conference/usenixsecurity12/sec12-final228.pdf).
- **Dan Boneh, Twenty Years of Attacks on the RSA Cryptosystem.** Обзор атак, включая
  малые экспоненты, Винера, broadcast-атаку Хастада и Franklin–Reiter, с условиями применимости.
  [Статья](https://crypto.stanford.edu/~dabo/papers/RSA-survey.pdf).
- **Handbook of Applied Cryptography.** Глава 3, алгоритм 3.14: Поллард p−1;
  глава 8, раздел 8.2.2(vi): общий модуль RSA.
  [Глава 3](docs/sources/handbook-applied-cryptography-chapter-3.pdf),
  [глава 8](docs/sources/handbook-applied-cryptography-chapter-8.pdf).
- **RFC 8017, PKCS #1 v2.2.** Спецификация RSAES-OAEP, включая случайное дополнение.
  OAEP устраняет условия показанных атак на короткое/повторяющееся сообщение без padding,
  но не исправляет факторизуемый модуль или слабую приватную экспоненту.
  [Спецификация](https://www.rfc-editor.org/rfc/rfc8017).

Эти примеры демонстрируют ошибки выбора параметров и использования RSA.
Они не показывают взлом корректно сгенерированного современного RSA-ключа с подходящей схемой padding.
