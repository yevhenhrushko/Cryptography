## 🚦 Готовность PR: ⚠️ ISSUES

Критических дефектов корректности нет. OAEP **эмпирически сверён с JDK** (`RSA/ECB/OAEPPadding`, SHA-256/MGF1) — encode/decode, MGF1 и формат EM корректны по RFC 8017 и совместимы с JCA в обе стороны. Генерация случайности, Миллер — Рабин, Garner CRT, отклонение `p·q≠n` при загрузке — проверены. Перед слиянием стоит закрыть два High и ключевые Medium (особенно M1-security: вводящий в заблуждение Javadoc про целостность).

**Сводка по важности:** High — 2 · Medium — ~14 · Low — ~15.

## 🔐 Безопасность (agent, с эмпирической проверкой)

### High
- **SEC-H1. «Учебный» RSA без padding — дефолтный путь шифрования и публичный API.** `Main.java:200` шифрует «Hello World!» рабочим 16383-битным ключом через `RsaHelper.encryptText` (`m^e mod n`, без padding); этот же ключ переиспользуют `FileCryptoDemo` и бенчмарк. Собственный тест подтверждает слабость: перешифрование догадки совпадает за 12.8 мс (`docs/rsa-key-benchmark-latest.txt:11`). Детерминировано, malleable, без целостности. → В `Main` шифровать через `RsaFileCipher.encrypt` (OAEP); `encrypt/decryptText/Bytes` вынести в `TextbookRsa` или переименовать в `rawEncrypt*` с Javadoc «примитив RSAEP/RSADP, не для данных».

### Medium
- **SEC-M1. `RsaFileCipher` не привязывает позицию/число блоков.** Блоки — независимые OAEP под одним ключом с пустой меткой; заголовок без счётчика блоков и MAC. Проверено: обмен двух блоков → 400 перепутанных байт без ошибки; усечение → 190 байт без ошибки. Javadoc (`RsaFileCipher.java:21-22`) про «обнаружение повреждённого файла» вводит в заблуждение. → Задействовать метку OAEP `L = MAGIC||version||int32(index)||int32(total)`, проверять `blocks==total`; в перспективе — гибрид RSA-OAEP + AES-256-GCM.
- **SEC-M2. Файл закрытого ключа: race + симлинк + проглоченный chmod.** `RsaHelper.java:412-413,422-428`. Между `writeString` и `setPosixFilePermissions` файл с `d,p,q` имеет umask-права (0644); `CREATE` (не `CREATE_NEW`) пишет по подложенному симлинку; при `IOException` ключ молча остаётся world-readable; `Keys/` создаётся 0755. → Писать через `newByteChannel` с `CREATE_NEW` и атрибутом `rw-------`; `IOException` пробрасывать; каталог — `rwx------`. (CWE-377/732/367)
- **SEC-M3. Декодирование OAEP не константно по времени.** `RsaFileCipher.java:199-209`: ранний `break` в скане разделителя — время зависит от расшифрованного DB, вопреки комментарию про защиту от оракула Мангера. Для CLI не критично, опасно за сервисом. → Сканировать весь DB без раннего выхода, integer-масками, одна финальная проверка.

### Low
- **SEC-L1.** Авто-`toString()` записей `RsaPrivateKey/RsaKeyPair/SavedRsaKeyPair` печатает `d,p,q` (`RsaHelper.java:60,77,86`). Переопределить.
- **SEC-L2.** Битая строка файла ключа утекает через `NumberFormatException`, который `Main` логирует (`RsaHelper.java:480,482`→`Main.java:217-218`). Обернуть парсинг.
- **SEC-L3.** `generateKeyPair` молча подменяет `e` при `gcd(e,φ)≠1` (`RsaHelper.java:136-143`). Бросать исключение. *(совпадает с ARCH-2)*
- **SEC-L4.** CRT без проверки результата (Bellcore fault): `decryptText/Bytes` вернут неверное `m` при повреждённом ключе. `if(!m.modPow(e,n).equals(c)) throw`. Нет blinding — для CLI ок, в Javadoc оговорить.
- **SEC-L5.** Закоммиченные отчёты содержат абсолютный путь `/Users/admin/...` (`docs/rsa-key-benchmark-latest.txt:2`, `docs/benchmarks/*.txt:2`). Печатать `getFileName()`.
- **SEC-L6.** `FileCryptoDemo` молча перезаписывает выходные файлы. `CREATE_NEW` или `--force`.
- **SEC-L7.** `logback-classic:1.5.17` — **CVE-2025-11226** (нужен Janino в classpath + контролируемый конфиг; здесь не эксплуатируется). Поднять до ≥ 1.5.19.
- **Не-security баг:** `Main.java:98-100` ставит `interrupt()` и на `ExecutionException` — ложный флаг прерывания.

## ⚡ Производительность (agent, с замерами на 16 CPU / Corretto 21)

Базовые замеры: CRT-расшифрование 16384-бит блока **191 мс** (без CRT 737 мс); один раунд Миллера — Рабина 8192-бит **94 мс**; `RsaKeyValidator.validate` **1.9 с** (serial); OAEP-шифрование 1 МБ **82 мс**.

### High
- **PERF-H1. Горячий цикл Ферма ~78% времени в `BigInteger.sqrt()` из-за слабого фильтра.** `RsaFermatBenchmark.java:104,233-241`. Единственный модуль 4032 пропускает 3.17%; `sqrt` 16384-бит = 809 мкс × 3.17% = 25.6 мкс из 33 мкс на кандидата. → Вести инкрементально ещё 1–2 остатка и требовать прохождения всех таблиц до `sqrt`: mod 4095 → 1.54%, +mod 12155 → 0.33% (оценка ~10× скорости). Плюс убрать 4 аллокации 2 КБ BigInteger на кандидата (вести `twoAPlusOne` инкрементально: 182 нс vs 297 нс) и вынести `BigInteger.valueOf(RESIDUE_MODULUS)` в константу.

### Medium
- **PERF-M1. `RsaKeyValidator.validate` заново гоняет 10 раундов Миллера — Рабина на уже подтверждённых простых**, serial на главном потоке (`RsaKeyValidator.java:117-119` ← `Main.java:166`). 1.88 с из 1.9 с — это два `isProbablePrime`. → Флаг «пропустить PRIMALITY» для уже проверенных, либо два вызова через `CompletableFuture` параллельно, либо меньше раундов здесь.
- **PERF-M2. 10 раундов подтверждения найденного простого идут serial на одном воркере**, пока 15 других жгут заведомо выбрасываемых кандидатов (`MillerRabinTest.java:67-94`, `Main.java:74`). Раунды независимы. → Дешёвый 1-раундовый скрин в воркере, затем подтверждение остатка раундов веером (`IntStream.range(1,rounds).parallel().allMatch`). ~0.94 с → ~0.1–0.2 с на простое.
- **PERF-M3. Предел пробного деления 1000 пропускает 15.3% кандидатов к 94 мс `modPow`**; сито до 65536 оставило бы 9.6% (`MillerRabinTest.java:20-29,50-58`). → Инкрементальное сито (как `BitSieve` в `BigInteger.probablePrime`): `b mod p_i` один раз, затем окно; предел можно поднять до 2^16 бесплатно.
- **PERF-M4. `pollardPMinusOne` делает полноширинный `modPow` на каждое малое простое без лимита времени** (`RsaAttackHelper.java:134-161`). При `bound=100000` и 16384-бит ключе ~2 часа, хотя Javadoc говорит «не лимит времени». CI гоняет только `bound≤19`. → Стандартная B-гладкая экспонента (`r^k ≤ B`, ~1.44·B возведений), gcd раз в ~100 простых, либо `Duration`-бюджет как в бенчмарке.
- **PERF-M5. При провале валидации `Main` выбрасывает оба простых и перезапускает оба 8192-бит поиска**, хотя доминирующий отказ — по-простому (`Main.java:147-172`). `e=11·9091·65537` → ~19% пар падают на `PUBLIC_EXPONENT`. → После каждого `generateProbablePrime` проверять `gcd(e,prime-1)==1` (53 мкс) и гладкость; перегенерировать только нужное простое. Парные проверки (`DISTANCE`, `SHARED_FACTOR`, `PRIVATE_EXPONENT`) оставить в финальном `validate`.

### Low
- **PERF-L1.** CRT-параметры (`dp,dq,qInv`) пересчитываются на каждый блок (`RsaHelper.java:197-202`): 1.84 мс из 191 мс (~1%); на 10.7 МБ ~0.6 с wall. Кэшировать в `RsaPrivateKey`. *(пересекается с ARCH-3)*
- **PERF-L2.** `shutdownNow()` не прерывает `modPow`; до 15 потоков живут ещё ~94–940 мс, пока следующий поиск стартует 16 новых — кратковременная переподписка ядер (`Main.java:94-103`). Переиспользовать один executor на весь прогон.
- **PERF-L3.** `x.modPow(TWO,n)` в цикле MR — 98 мкс vs 47 мкс у `x.multiply(x).mod(n)` (`MillerRabinTest.java:80`). Бесплатный 2× на строке.
- **PERF-L4.** `RsaFileCipher.decrypt` держит вход + `parts` + `plain` одновременно (~3× размера файла). На 10 МБ ок; для больших нужен стриминг.
- **PERF-L5.** `integerRootFloor` — бисекция с `pow` на шаг (`RsaAttackHelper.java:440-452`); Ньютон сошёлся бы за O(log log). Сейчас < секунды — информационно.
- **PERF-L6.** `RsaAttackHelper.fermat` пересчитывает `a*a−n` каждую итерацию вместо инкремента (demo использует 100 итераций) — некритично.

### Замеченная несогласованность
`RsaFermatBenchmark.java:117` Javadoc говорит «не более одного часа», `MAX_DURATION` (строка 27) и `build.gradle:54` — иные значения, а `RsaPublicKeyAttackTest.java:32` имеет `@Timeout(200)`. При бюджете > ~180 с тест упадёт. Свести к одному значению.

## 🏗️ Архитектура (ручной разбор)

- **ARCH-1 (med).** Единый статический `SecureRandom` в `PrimeCandidateGenerator:11` делится всеми потоками поиска — точка contention. → `ThreadLocal<SecureRandom>`.
- **ARCH-2 (med).** `MillerRabinTest` (пакет `primality`) тянется в `PrimeCandidateGenerator` (пакет `generator`) ради `getRandomInRange` (`MillerRabinTest:69`) — инверсия слоёв. → Вынести в общий util.
- **ARCH-3 (med).** `RsaHelper` (489 строк) смешивает криптопримитивы и сериализацию ключей (PEM-подобный save/load). → Выделить `RsaKeyStore`.
- **ARCH-4 (med).** Рассогласование по `e`: `generateKeyPair` молча инкрементирует `e`, а `RsaKeyValidator`/`Main` требуют ровно `e`. В потоке `Main` ветка мёртвая, но прямой вызов вернёт другой `e` без предупреждения. *(= SEC-L3)* → Единое поведение.
- **ARCH-5 (low).** Три точки входа (`Main`, `FileCryptoDemo`, `RsaAttackDemo`) — приемлемо для учебного проекта.

- **CPLX-2 (low).** `MillerRabinTest.isProbablePrime` 59 строк, `Main.generateProbablePrime` 50 строк с вложенной лямбдой — плотно, но читаемо.
